# 出口代理与设备连接

[返回文档目录](README.md) · [项目首页](../README.md)

| 功能 | 用途 | 请求去向 |
| --- | --- | --- |
| 账号出口代理 | 为账号指定上网出口 | 容器 → 服务端 HTTP 桥接 → 代理池中的代理 → 外部服务 |
| abox-link | 浏览设备上共享的文件夹并按需上传文件 | 设备通过 HTTPS/WSS 连接 AgentBox |

每种功能可以独立使用。默认网关地址 `172.17.0.1` 只是 Docker 默认网桥的常见值，部署前应核对实际网络。

## 账号出口 IP 代理

给账号绑一个出口 IP：绑定后，**这个账号的一切官方请求都从该 IP 出去**——容器里
`claude`/`codex` 打的模型接口，以及服务端代发的 OAuth 换令牌、订阅查询、Key 连通性
探测。多个订阅账号共用一台服务器时，这是把它们的来源 IP 分开的办法。

在「系统设置 → IP 代理」里维护代理池（增删改、连通性探测、批量导入导出），再到
「账号池 → 编辑 → 出口 IP 代理」为账号选一个。改动对新对话与新开的终端立即生效，
不必重启容器。

几个需要知道的行为：

- **代理池里多是 SOCKS5，而容器里的 claude 是 Node 客户端，只认 http(s) 代理。**
  所以 agentbox 在网桥网关上起一个本地 HTTP 代理（`proxy_bridge`），容器只跟它说
  HTTP 代理协议，SOCKS5 那一段由服务端走完。代理池非空时自动启动。
- **绑了代理就绝不退回直连。** 代理停用、配置坏掉或桥接没绑上时，请求会直接报错，
  而不是悄悄改用服务器自己的 IP——后者正是绑定代理要避免的事。
- **注入的是全局 `HTTP(S)_PROXY`**（大小写各一份，外加 `NO_PROXY` 放行本机与网桥）。
  遵循这些代理环境变量的 `git clone`、`npm install` 等命令同样走这个出口；这不是容器网络层的强制流量重定向。
  需要强制时打开下面的「受限出网」。
- 每个账号在桥接上的口令由服务端 `auth_token` 派生，互不相同；桥接要求提供对应账号的口令。
  修改 `auth_token` 并重启服务后，口令随之轮换，已运行进程需更新环境。
- 批量导入支持 `scheme://user:pass@host:port`、`host:port:user:pass`、`host:port`
  三种写法，可用 `#名称` 结尾；不写协议按 SOCKS5 处理。导出的文本**含密码明文**。

## 受限出网

默认（`container.egress` 为空或 `"open"`）工作空间在 Docker 网桥上可以直连外网：
不读代理变量的程序或 `curl --noproxy '*'` 会从服务器自己的 IP 出去，还能连到宿主机上
监听 `0.0.0.0` 的服务（sshd、数据库等）以及同一网桥上的其他工作空间。

在「系统设置 → Agent 镜像与资源限制 → 出网范围」选「受限」（即 `"container": {"egress": "restricted"}`）后：

- 每个工作空间的网络命名空间里装一组 iptables 规则（链 `ABX_EGRESS` / `ABX_INGRESS`）。
  只放行到 agentbox 自己给容器的地址：账号代理桥、模型网关、
  用量回传，以及临时桥接端口段 `proxy_bridge.dynamic_ports`（默认 `30000-30999`，Git 传输、
  Git 终端凭据和委派 MCP 用）。其余 TCP 立即被拒绝，UDP/ICMP 和 DNS 也不放行，
  入站新连接全部丢弃，IPv6 只留回环。
- 绑了代理的账号照旧走自己的代理；**未绑代理的账号也会注入代理变量**，行为由
  「未绑代理的账号」（`container.unbound_egress`）决定：
  - `server`（默认）：桥接从服务器直连目标，出口 IP 与以前相同。桥接只连公网地址：回环、私网、
    链路本地、CGNAT、保留网段和宿主机自身网卡上的地址都会被拒绝（502）。注意空间仍可通过
    IP 回显服务（如 ifconfig.me）看到服务器的真实公网 IP。
  - `none`：桥接直接拒绝（502），这些账号没有任何外网，包括模型接口，直到绑上代理。
    要让任何工作空间都查不到服务器 IP，需选这一项，或给所有账号都绑上代理。
- 规则由一次性的网络辅助容器（`container.egress_image`，默认 `agentbox-network:latest`）写入，
  它与工作空间共享网络命名空间、只有 NET_ADMIN，写完即退出；Agent 进程仍是 UID 1000，
  没有权限改规则。镜像不存在或规则装不上时，空间启动直接报错，不会退回直连。
- 新启动的空间在启动时加锁；已在运行的空间由后台巡检在约 10 秒内补上。已建立的连接不会被切断。
  切回「开放」只对重新启动的空间生效。
- 「不受限的用户」（`container.egress_exempt_users`，如 `["boxadmin"]`）的空间不加锁、不注入
  未绑代理账号的桥接变量，行为与开放模式相同，供管理员在空间里维护服务器。名单只对之后启动
  或巡检的空间生效；已加锁的空间要重启才会解除。旧客户端保存设置时不带该字段，服务端保留原名单。
- 不需要域名解析的工具照常工作；直接解析外部域名、走 SSH 的 `git` 等会失败，
  需要改成经代理（HTTPS 远程、`HTTPS_PROXY`）的方式。
- 广播给容器的地址（例如 `proxy_bridge.host`）必须是具体的 IPv4 地址；
  是 `0.0.0.0` 这类通配地址时无法开启。

## Общие папки через abox-link

1. В настройках безопасности AgentBox включите «Разрешить подключение устройств».
2. Установите abox-link той же версии, что и сервер. На странице «Подключить устройство» сгенерируйте одноразовый код и вставьте его в панель клиента.
3. Добавьте папки в abox-link и подключите устройство. В рабочем пространстве откройте «Файлы → С моего компьютера».

Список файлов читается с компьютера по запросу. При копировании в рабочее пространство или прикреплении к чату выбранный файл загружается на сервер. При отключении устройства новые передачи приостанавливаются. Чаты и ранее скопированные файлы доступны независимо от устройства.

Панель клиента доступна на http://127.0.0.1:7801. После сопряжения слева отображаются добавленные папки компьютера, справа — файлы выбранного рабочего пространства. Выберите файлы и нажмите «На сервер» или «На компьютер». При совпадении имён можно заменить файл, сохранить оба или пропустить. Для копирования с компьютера обновите AgentBox и abox-link до одной версии.

В «Настройках подключения» можно включить запуск при входе и автоматическое подключение к AgentBox. Если системное окно выбора папки недоступно, там же можно ввести её абсолютный путь.
